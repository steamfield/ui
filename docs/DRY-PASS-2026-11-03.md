# DRY pass across consumers, 2026-11-03

A read-only survey of every consumer's `main` (opendata from its uncommitted migration worktree) after the 0.2.0 migrations, revised after a devil's-advocate review that checked each recommendation against the code. It answers two questions: where does a repo still carry its own copy of something `@steamfield/ui` already ships, and what else is duplicated between repos that might belong in the library. Nothing here has been changed yet.

The bar for "should move into the library" is the one in AGENTS.md: the code is UI behavior (not product copy or site look), several repos carry it, and sharing it removes a rule that would otherwise drift (accessibility, reduced motion, no-JS, FOUC). A thin wrapper around a browser API with no such rule doesn't qualify, and neither does an option with one user.

The headline result: no library change is needed. Every worthwhile item below migrates onto 0.2.x as it is, and the four library options the first draft proposed didn't survive a count of real users (section 2).

## 0. Prerequisite: opendata isn't on 0.2.x

opendata's migration worktree depends on `"@steamfield/ui": "file:/Users/riley/Projects/.sfui-worktrees/_dist/steamfield-ui-0.0.0.tgz"` in `frontend/package.json:57`, `blog/package.json:21` and `shared/package.json:6`. That's a pre-release tarball on an absolute path, so it can't install in CI or on another machine. Before that migration lands it has to move to `~0.2.0` from npm, which brings the 0.2.0 markup change (`tool-paren` spans inside `tool-args`) and may need test adjustments, as decks did. Every opendata row below waits on this.

## 2. Library options considered and rejected

1. **`usePlayback` interval mode.** One real user, rr `MonitorStage`. kelvo's `useOnScreenInterval` (27 lines) is already the right composition: `usePlayback({ threshold: 0, reducedPolicy: "hold" }).playing` gating a `setInterval`. steamfield and openchart want that composition too. Instead, document the `playing` + timer pattern in the README's playback section.
2. **`spyToc` `onChange`.** The React TOCs can style `aria-current` instead of holding state. The only one that needs a callback (the blog side rail) can't use `spyToc` without a markup change anyway.
3. **A latching near-viewport helper.** `use-near-viewport.ts`'s comment is about opendata's own `useInView`, which forces visible under reduced motion. The library gate's `inView` is already independent of reduced motion (`src/playback/gate.ts:186-191`). The other users are plain 10-15 line latching observers with no motion or a11y rule, so a wrapper around IntersectionObserver isn't worth owning.
4. **`DocsConfig.groups` as `{ id, label }` and an llms intro option.** rr's and decks' `llmsIndex` / `llmsFull` emit a deliberately different format (no `.md` paragraph or Optional section, `title` not `label`, no `Source:` lines, different joins; rr `lib/docs.ts:3-4, 90-114`). Labelled groups wouldn't let them drop it. Group ids map to labels in one line at the call site. The intro option has one user, stacks-api, whose string replace only keeps one sentence's position in llms.txt; moving that note into `intro` is fine. rr and decks either accept the library's llms output or keep theirs.

## Suggested order

1. Move opendata's migration onto `~0.2.0` from npm (section 0). That blocks the migration landing.
2. Small consumer fixes on 0.2.x, each with a real gain: `gif.tsx` onto `usePlayback`, steamfield `DecksDemo` onto `usePlayback`, `CopyCitation` and `in-app-browser-notice` onto `copyText`, stacks-api's search and explorer copy buttons onto a scoped `enhanceCopyButtons`, the three TOCs onto `spyToc`, rr `FlowDiagram` onto `usePlayback`, openchart's copy buttons onto `useCopy`. Also document the `playing` + timer pattern in the README, and fix opendata's theme flash.
3. decks `site/` onto the library, as its own piece of work: reveal re-key, markdown CSS re-point, and a decision on its llms format. rr's markdown move goes with it, since both need the same CSS re-point.
4. opendata talks onto `slidev-addon-decks`, after aligning openchart versions and publishing the addon.

No library release is needed for any of it.
