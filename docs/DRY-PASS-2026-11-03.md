# DRY pass across consumers, 2026-11-03

A read-only survey of every consumer's `main` (opendata from its uncommitted migration worktree) after the 0.2.0 migrations. It answers two questions: where does a repo still carry its own copy of something `@steamfield/ui` already ships, and what else is duplicated between repos that might belong in the library. Nothing here has been changed yet; this is the input for deciding what to refactor next.

The bar for "should move into the library" is the one in AGENTS.md: the code is UI behavior (not product copy or site look), at least two or three repos carry it, and sharing it removes rules that would otherwise drift (accessibility, reduced motion, no-JS, FOUC). Site styling that happens to look alike stays per site. Two near-identical files that change for different reasons are better left as two files than joined through a wrong abstraction.

## 2. Library gaps the leftovers point at

Each of these is a small, additive option, and each one unlocks several leftovers above.

1. `usePlayback` interval mode (`tickMs`, maybe `phaseMs`). Users: rr `MonitorStage` and `FlowDiagram`, steamfield `DecksDemo`, openchart `useSimTick`, and kelvo's `useOnScreenInterval`, which could then shrink to nothing. Five consumers carrying the same "tick only while on screen, tab visible and motion allowed" rule.
2. `spyToc` `onChange(id)` and an initial mark of the first heading. Users: three opendata TOCs and steamfield's. The React ones would keep their scroll-into-view behavior on top of the callback.
3. A latching "near viewport" primitive (`once: true` on the gate, or a `whenNear(el, cb, { rootMargin })` helper). opendata's `use-near-viewport.ts` already builds this over `createPlaybackGate` by forcing motion on so reduced-motion users don't fire every gated fetch at once, which is a rule that should live in the library, not in a comment. Other users: kelvo `DashboardDemo` iframe load, openchart `Demo` lazy mount, opendata `gif.tsx` and `interactive-example.tsx`.
4. `DocsConfig.groups` accepting `{ id, label }` and an intro placement option for `llmsIndex`. Users: rr (would drop its local llms helpers) and stacks-api (would drop its string-replace post-processing in `lib/docs.ts`).

Not worth a library change: image copy via `ClipboardItem` (one call site), and a reveal attribute option (re-keying stacks-api's chart CSS is cheaper).

## Suggested order

1. Consumer leftovers that need no library change: decks `site/` onto the library, openchart and stacks-api copy calls, opendata clipboard sites, stacks-api chart reveal, `terminal-gif-frame`. Mostly mechanical, each gated by the repo's own tests and a screenshot diff.
2. The four library options in section 2 (one minor, 0.3.0), then the leftovers they unlock: rr and steamfield playback, the four TOC spies, the near-viewport hooks, rr's docs helpers. rr's and decks' markdown move also needs their CSS re-pointed onto the library's `data-*` hooks.
3. A `theme` subpath, if you agree it belongs here.
4. opendata talks onto `slidev-addon-decks`, which is a decks/opendata task rather than a library one.
